# Создание вакансии голосом

Голосовой помощник помогает создать вакансию: принимает основные сведения и условия, задаёт четыре вопроса и формирует редактируемое описание. Даже короткие ответы раскрываются с учётом должности и общего контекста. Пользователь проверяет результат и сохраняет вакансию.

[Открыть прототип](https://trueakaru-stack.github.io/iskra-vacancy-prototype/) · [Презентация в PDF](docs/voice-vacancy-presentation.pdf) · [Презентация в PowerPoint](docs/voice-vacancy-presentation.pptx)

## Сценарий

1. Нажмите «Добавить вакансию».
2. Назовите должность, регион и опыт. Затем расскажите об условиях работы. Оба этапа требуют ответа.
3. Ответьте на четыре вопроса. Кнопка микрофона начинает запись; «Стоп» отправляет её на распознавание. Можно вводить и исправлять текст вручную.
4. Проверьте основные поля и четыре раздела описания. Все значения можно изменить.
5. Сохраните вакансию. Откроется таблица, новая строка мигнёт пять раз. Нажатие на строку открывает просмотр и редактирование, корзина удаляет вакансию.

Сохранённые вакансии, правки и удаления остаются после обновления в этом браузере. Очистка данных сайта удалит их. Общего хранилища организации в демонстрации нет. В исходном списке использованы вымышленные данные.

## Запуск

Нужны Node.js и pnpm из поля packageManager. Выполните `pnpm install`, затем `pnpm run build:design-system`. Для сборки укажите `VITE_GENERATION_URL` — адрес метода `/generate` голосового помощника — и выполните `pnpm exec vite build`. Проверки: `pnpm run typecheck` и `pnpm test`.

Клиент лежит в `src/`, сервис помощника — в `worker/`. Ключи сервиса не передаются в браузер. Для записи нужен HTTPS и разрешение микрофона. Без подключённого сервиса доступны оболочка и ввод текста, но реальная обработка и генерация не выполняются.

## Основания интерфейса

Доступные публичные руководства показали несколько экранов существующего продукта. Полную информационную архитектуру и все рабочие состояния проверить не удалось. Оболочка и место нового сценария предварительны: они продолжают доступную стилистику и требуют проверки с командой продукта. Интеграция с действующим продуктом не имитируется.
