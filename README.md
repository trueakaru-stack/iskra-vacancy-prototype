# Создание описания вакансии — прототип

Прототип для тестового задания UX/UI Frontend. Он показывает, как заказчик может ответить на четыре вопроса голосом или текстом, получить редактируемое описание и сохранить демонстрационный черновик. Это самостоятельная демонстрация сценария: она не подключается к действующей «Искре» и не публикует вакансии.

## Как пройти сценарий

1. В списке вакансий нажмите «Добавить вакансию». Укажите известные данные; название понадобится для сохранения.
2. На шаге «Описание вакансии» отвечайте на вопросы по одному. Для записи нажмите микрофон, затем «Стоп». Распознанный ответ можно исправить вручную.
3. Проверьте ответ и нажмите «Далее». «Назад» возвращает к предыдущему ответу. Круг вокруг микрофона отражает заполненность четырёх ответов: 25% за каждый непустой ответ.
4. После четвёртого ответа создайте описание, проверьте и отредактируйте блоки. Нажмите «Сохранить»: черновик появится в таблице и откроется повторно по нажатию на строку.

Степпер показывает этапы создания вакансии. Для перехода используйте кнопки «Назад» и «Далее».

Поиск, сортировка и фильтр региона работают на демонстрационных данных. Черновики хранятся только в памяти вкладки: после обновления или закрытия они пропадут. Не вводите реальные персональные или конфиденциальные данные для демонстрации.

Для голосового ввода нужен браузер с поддержкой MediaRecorder, доступ к микрофону и сеть. После нажатия «Стоп» аудио отправляется на распознавание в Cloudflare Workers AI; приложение не сохраняет его на сервере. Если обработка не удалась, ту же запись можно отправить повторно, пока открыта вкладка, или ввести ответ вручную. Ответы для генерации описания также отправляются в Cloudflare Workers AI; результат модели необходимо проверить перед использованием.

## Что реализовано

- Список вакансий по предоставленному референсу, поиск, фильтр и сортировка.
- Четыре исходных вопроса, возврат и сохранение введённых ответов в рамках вкладки.
- Непрерывный круг заполненности, запись, отображение уровня звука, остановка, обработка, успех и ошибка.
- Форма проверки, редактирование блоков и демонстрационный черновик.
- Worker с моделями Whisper для речи и Qwen для описания; запросы проверяются и не требуют ключа в браузере.

## Что не входит в прототип

- Настоящая интеграция с «Искрой», публикация вакансий и хранение на сервере.
- Семантическая оценка полноты: круг показывает факт наличия текста, а не его качество.
- Автоматическая гарантия достоверности текста модели; ответ остаётся на проверке человека.
- Тёмная тема и другие сценарии подбора, включая подключение существующих вакансий.

Реальная генерация подключена к развёрнутому Worker и проверена на одном наборе вымышленных ответов. Состояния, которые ещё не проверены в целевом браузере, перечислены в [проверках](docs/verification.md).

## Для разработки

Нужны Node.js не ниже 22, pnpm 11.25 и доступ к сети для установки зависимостей. Сборка не изменяет исходную библиотеку NeoBook на компьютере: в проект включены используемые компоненты и необходимые зависимости.

```sh
pnpm install --frozen-lockfile
pnpm run build:design-system
pnpm test
pnpm run typecheck
pnpm run build
```

При настройке размещения задайте `VITE_GENERATION_URL` как полный HTTPS-адрес `/generate` развёрнутого Worker. В `worker/wrangler.toml` задайте `ALLOWED_ORIGIN` равным точному origin интерфейса. В Worker должен быть привязан Workers AI под именем `AI`. CORS ограничивает вызовы из браузера, но не является защитой от прямых запросов: перед публичным использованием нужны отдельные ограничения доступа и расхода.
